# Формат рецепта для «Готовим вместе»

Рецепт — это отдельный JSON-файл. Приложение ничего не знает о конкретных блюдах: оно читает список рецептов из `recipes/index.json`, загружает каждый файл, проверяет его и показывает в «Книге рецептов». Рецепт можно также добавить из файла прямо на устройстве.

Собирать рецепт удобнее всего в «Рецепторе» — графическом редакторе: https://romanglebov.github.io/gotovim-vmeste/editor/. Он пишет ровно этот формат.

Чтобы подключить новый рецепт к библиотеке:

1. Положите файл в папку `recipes/`, например `recipes/omelette.json`.
2. Допишите имя файла в `recipes/index.json`:

```json
{ "format_version": 1, "recipes": ["mushroom_soup.json", "pasta_tomato.json", "omelette.json"] }
```

## Верхний уровень

| Поле | Обязательно | Что это |
|---|---|---|
| `format_version` | да | Версия формата. Сейчас `1`. Приложение откажется открыть рецепт более новой версии, чем умеет. |
| `id` | да | Уникальный идентификатор рецепта латиницей: `mushroom_cream_soup`. По нему статистика разных готовок сводится вместе. |
| `version` | нет | Версия самого рецепта. Увеличивайте, когда меняете шаги, чтобы старая статистика не смешивалась с новой. |
| `title` | да | Название блюда. |
| `image` | нет | Картинка блюда для плитки в «Книге рецептов», путь относительно папки `recipes/`: `images/shakshuka.svg`. Подойдут SVG, PNG, JPG, лучше в пропорции 4:3. |
| `icon` | нет | Значок, который показывается, если картинки нет: `🍳`. |
| `base_servings` | нет | На сколько порций рассчитаны количества. |
| `players` | нет | `{ "min": 1, "max": 3 }` — сколько поваров имеет смысл. По умолчанию 1–3. |
| `equipment` | да | Инвентарь. Показывается на экране «Вам понадобятся» и ограничивает, сколько шагов могут идти одновременно. |
| `ingredients` | да | Продукты для экрана «Вам понадобятся». |
| `fallback_tasks` | нет | Дела не по рецепту («помыть посуду»). Сейчас в рецептах их нет: на экране только шаги готовки. |
| `steps` | да | Шаги рецепта. |

## Инвентарь

```json
{ "id": "board", "name": "Разделочная доска", "count": 2, "icon": "🪵", "image": "images/board.png" }
```

`icon` и `image` нужны для плиток на экране «Вам понадобятся». `image` — картинка предмета (путь относительно папки `recipes/`, как и у картинки блюда); если её нет, показывается `icon`. У рецепта, добавленного из файла прямо на устройстве, папки нет, поэтому картинки в нём работают только встроенные (`data:`-адрес); иначе показываются значки. Пока у всех предметов стоят значки-заглушки, позже их можно заменить фотографиями, не меняя приложение. Те же два поля есть и у продуктов.

`count` — сколько таких предметов на кухне. Если у шага в `resources` указана доска, а досок две, то два шага с доской могут идти одновременно, третий подождёт. Конфорки — тоже инвентарь: `{ "id": "stove", "name": "Конфорка", "count": 2 }`.

## Продукты

```json
{ "id": "cream", "name": "Сливки 20%", "amount": 200, "unit": "ml", "optional": false }
```

Единицы: `g`, `ml`, `pcs`, `tsp`, `tbsp`, `pinch`, `handful`, `bunch`, `to_taste` (тогда `amount` равен `null`).

## Шаг

```json
{
  "id": "fry_onion",
  "title": "Обжарить лук",
  "station": "stove",
  "item": "суп",
  "description": "Положите лук и жарьте 5–7 минут, помешивая лопаткой, пока он не станет мягким и прозрачным. Если начал темнеть, убавьте огонь.",
  "ingredients": [],
  "technique": "saute_stir",
  "depends_on": ["melt_butter", "dice_onion"],
  "resources": ["pot", "stove", "spatula"],
  "help": null
}
```

| Поле | Что это |
|---|---|
| `id` | Уникальный внутри рецепта. |
| `title` | Короткое название действия, начинается с глагола. |
| `station` | Пост, где делается шаг: `sink` (раковина), `board` (доска), `counter` (стол), `stove` (плита), `appliance` (техника). Кто работает на посту, тому и предлагаются следующие шаги этого поста. |
| `item` | Продукт или заготовка, с которой работает шаг: «лук», «картофель», «суп». Кто помыл перец, тому предложат его же резать. На экране не показывается. |
| `description` | Что именно сделать. Это единственный текст на экране, кроме названия. Если шаг — жарить, варить или тушить, напишите здесь же, **до какого состояния** и примерно сколько минут: «жарьте 5–7 минут, пока лук не станет мягким и прозрачным», «яйца готовы, когда белок полностью белый, а желток колышется». Таймеров нет: плиты у всех разные, поэтому решает повар. Очевидное («картошка помыта, когда на ней нет земли») не пишите. |
| `ingredients` | Какие продукты из списка `ingredients` рецепта впервые попадают в работу на этом шаге: `["onion"]`. По ним «Рецептор» рисует плитки продуктов слева от шага. Если продукт нужен в двух шагах (соль), укажите его в обоих. |
| `technique` | Название техники для будущей библиотеки роликов (`dice_onion`, `saute_stir`). Пока на экране не показывается. |
| `depends_on` | Какие шаги должны быть закончены до этого. Порядок шагов в файле не важен для логики, но в этом порядке шаги листаются на телефоне, поэтому пишите их в естественной последовательности. |
| `resources` | Какой инвентарь шаг занимает, пока идёт. |
| `late` | `true` для дел, которые нужны только в конце: накрыть на стол, нарезать хлеб. Они предлагаются последними. |
| `help` | Чем может помочь второй повар, или `null`. |

### Какой шаг предложат дальше

Свободный повар сразу получает следующий шаг, ничего выбирать не нужно. Шаг выбирается так:

1. Продолжение только что сделанного шага: помыли перец → удалить из него семена.
2. Тот же продукт, затем тот же пост: кто у доски, продолжает резать.
3. Шаг, после которого откроется больше всего других.

Шаги на посту, где уже работает другой повар, отодвигаются назад, а шаги с `late` — в самый конец. Следующие три варианта показываются плитками под кнопкой «Готово»: нажали плитку — занялись этим шагом, а прежний вернулся остальным.

### Помощь

```json
"help": { "type": "split", "text": "Почистите вторую картофелину." }
```

- `split` — работу можно разделить пополам.
- `assist` — второй человек помогает, но не делает то же самое («придержите кастрюлю»).

Если помощь не имеет смысла (жарить вдвоём нельзя), ставьте `null`: освободившемуся повару предложат другие шаги.

## Что проверяет приложение при загрузке

- есть все обязательные поля;
- `id` шагов не повторяются;
- каждая зависимость ссылается на существующий шаг;
- каждый ресурс шага есть в инвентаре;
- в зависимостях нет циклов;
- пост шага один из пяти известных.

Если что-то не так, рецепт не загрузится, а приложение покажет, какой шаг и что именно исправить.

## Советы по разметке

- Один шаг — одно законченное дело над продуктом: «Почистить и нарезать лук», «Помыть и почистить картофель». Не дробите то, что один человек всё равно делает подряд.
- Указывайте только настоящие зависимости. Чем меньше лишних связей, тем больше шагов можно делать параллельно.
- Признак готовности в `description` должен проверяться глазами, носом или ножом, без часов.
- Не делайте отдельных шагов-ожиданий («Ждём, пока вода закипит», «Суп варится»). Ожидание — часть шага, который его запускает: «Вскипятить 3 литра воды», «Сварить спагетти: варите 8–10 минут, пока…».
- Не включайте плиту раньше времени: растопка масла зависит от нарезки лука, иначе масло пригорит, пока кто-то режет.
- Подготовку, которую можно сделать заранее и вне плиты, оставляйте без зависимостей — это работа для тех, кто только что освободился.
